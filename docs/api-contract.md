## Endpoints used

All paths below have prefix `/api/v1/dashboard`. REST data is unwrapped from the envelope. Default SSE messages contain the raw snapshot, not an envelope. Server live frames include `tickMs`, currently 1500 ms; heartbeat comments occur every 15 seconds.

- GET `/streams/live`, SSE `/streams/live/stream`: `LiveStreams`.
- GET `/usenet/live`, SSE `/usenet/live/stream`: `LiveStats`, with metrics in `live` and providers in `pool.providers`.
- GET `/streams/bandwidth?window=24h|7d|30d`: `BandwidthOverview`.
- GET `/streams/history?limit=20&offset=0&username=...&transport=...&q=...`: `{ entries: StreamHistoryRow[], total: number }`. Search parameter is **q**, not search.
- GET `/usenet/stats?window=24h|7d|30d|all`: `UsenetStatsOverview` including providers, indexers, and aggregate throughput.
- DELETE `/streams/sessions/:id`: `{ stopped: true }`, 404 if absent. Only invoked after a confirmation.

## Semantics and assumptions

- Current main is the supported contract. Older releases or forks may lack these endpoints or fields. Runtime checks detect major incompatible snapshots; declarations are not a full schema validator.
- Timestamps are epoch milliseconds. Sizes/speeds use bytes/bytes per second, displayed in base-1024 units.
- `(start + currentBytes) / size` is the newest range read’s file position (clamped), not playback time or unique bytes transferred. Upstream `start` is the range’s byte offset; `currentBytes` counts only bytes served in that read and resets on a new request. With no active reads, upstream reports zeroed position fields: the app shows Unavailable and hides the bar rather than claiming 0%. Unknown size has no progress percentage. `bytesServed` can exceed size after rereads. Verified against `packages/core/src/stream-sessions/types.ts`, `registry.ts`, and `service.ts` at the same source commit on 2026-10-05.
- The overview's usage card shows `periodTotal`. The chart uses `series`. The `30d` window follows `periodMode`: rolling 30 days or the configured monthly reset period (not necessarily the calendar month). `periodTotal` and global limits describe the accounting period even when history displays 24h/7d.
- Overview provider health uses the 24h stats window; Usenet/provider details select 24h/7d/30d/all and preserve the selected window when navigating between those screens. A provider's live chart is sampled from `pool.providers[].throughput` while the app is open. There is no invented historical per-provider graph endpoint. Acquired connections are labeled “in use”, since acquired includes work not currently moving bytes.
- Indexer rates include degraded imports as successful, matching upstream. No grabs is displayed explicitly rather than treated as an outage.
- Historical lists/stats refresh at 60 seconds by default (configurable to 30). Live fallback polls at 15 seconds by default (15/30/60 choices); SSE reconnect attempts are bounded to once per minute. Updates pause while hidden; live graphs retain only 30/60/120 samples in memory.
- Same-origin serving at `/mobile/` reuses the existing admin cookie. It does not bypass dashboard authorization. Cross-origin cookies may be blocked by SameSite Strict even with CORS; use a same-origin reverse proxy instead. No token/password login UI or new backend is introduced.
- The shell is available offline; authenticated data is not persisted. Reloading offline shows no old dashboard data. Live authentication, deployment, and physical iPhone installation remain unverified until tested against the user's instance.

## Live logs (local extension, 2026-10-03)

Inspected the same upstream snapshot before coding. Sources: `packages/server/src/routes/api/dashboard/index.ts` (logs routes/parseQuery), `packages/core/src/logging/ring-buffer.ts` (vendored LogRecord/LogQuery and query/clear semantics), `packages/core/src/logging/logger.ts`, `packages/core/src/logging/redact.ts`, and `packages/frontend/src/app/dashboard/logs/use-log-stream.ts`. Declarations are in `src/api/logTypes.ts`; response buffer statistics mirror the route and ring stats.

- GET `/logs`: envelope data `{ logs: LogRecord[], nextSeq, bufferStats: { entries, bytes, maxBytes, maxEntries, lastSeq } }`. Each record has `seq`, `ts`, `level`, optional `module`, and raw NDJSON `line`. Initial request is `limit=200&order=asc`. The server selects the newest matching entries before ordering them.
- Filters: `q` is case-insensitive substring matching across the raw line (including metadata); `regex=true` uses a case-insensitive regular expression. `level` and `module` are comma-separated selections. **since is an exclusive sequence cursor; until is an inclusive epoch-millisecond timestamp.** Limits are clamped to 1–5000, default 1000. An invalid regex matches nothing upstream; the app flags it before opening a feed.
- SSE `/logs/stream`: each event is `id: <seq>` and `data: <raw line>`, not a LogRecord wrapper or REST envelope. The first connection uses `since=nextSeq` from the initial snapshot. The browser's `Last-Event-ID` header takes precedence on native reconnect. Backfill selects the newest matching retained lines and replays oldest first, followed by individually filtered live records. Comment heartbeat `:hb` runs every 15s and is invisible to EventSource handlers.
- `nextSeq` is the global latest sequence, including nonmatching records. It is safe to advance the REST cursor across nonmatches. Replayed sequences are deduplicated; no client-generated IDs or timestamps are sent to the API. Healthy quiet OPEN sockets do not trigger REST fallback. Only unsuccessful connection/reconnection after 30s enters fallback: polling at max(30s, configured fallback interval), while native EventSource keeps reconnecting. CLOSED sources are recreated at most once per 60s. A bounded REST probe discovers session expiry; 401/403 (and existing `/login` redirects) suspend traffic.
- GET `/logs/export?format=log|json`: **both currently write raw NDJSON**, including the `.log` file. `json` is served as `application/x-ndjson`, not a JSON array. The upstream export iterates every retained match and ignores query limit/order. The app preserves active search/regex/level/module filters and fetches this endpoint with the existing cookie. It does not reconstruct an export from its capped visible rows. Extra client masking is applied to the received lines before download; a 20MB response ceiling prevents an unbounded mobile allocation.
- POST `/logs/clear`: JSON `{ "confirm": true }`, envelope data `{ cleared: true }`; otherwise 400 confirmation error. It clears **the complete server retained buffer**, regardless of viewer filters, without resetting sequences or stopping subscribers. Upstream then emits a warning audit record. The app confirms, clears its own visible/pending windows on success, and retains its EventSource. Mutation tests use fixtures only.
- Supported textual levels: fatal, error, warn, info, debug, trace. No module catalogue route exists; the app derives up to 100 names from received entries in the current viewer session.

Logs are retained upstream in a byte/entry-bounded process-local ring, not durable history. Restarting the process resets sequences; a REST refresh/reopening Logs recovers that reset. No healthy-feed periodic probe is added solely to detect restarts. Retention eviction and mobile caps can remove older records; seamless replay is limited to what the server still retains.

Upstream normally redacts credential-shaped top-level strings and URL credentials, but `LOG_SENSITIVE_INFO` can disable that protection and arbitrary nested metadata is not universally redacted upstream. AIOMobile additionally masks nested credential/header/cookie fields and recognizable credential text for display, copying and downloads. This is pattern-based protection, not a guarantee that arbitrary prose never contains sensitive content. Leave sensitive server logging disabled and treat downloaded troubleshooting logs as private.


## Read-only instance monitoring (2026-10-06)

System, tasks and library contracts were inspected at the supported `70ffb17a7bb99dd73dbab257af040b04f56eaa42` commit. Media Info uses newer upstream `147773cb80d5fd38a1dae7924b6b610abf1d92a9`. Read-only container inspection confirmed the running nightly image contains and mounts `/media-info`, with matching shipped summary/prober/attempt declarations. This confirms deployed code support, not authenticated production responses. No live provider/indexer/stream activity was tested.

- GET `/system`, SSE `/system/stream`: CPU/process/system memory/disk/uptime, raw SSE metrics every 5s. Overview uses process CPU, RSS and uptime with optional system details. System metrics are not presented as container quotas. The API's optional historical sample buffer is omitted from the compact card's in-memory projection.
- GET `/tasks`: `{ tasks, instanceId }`, shown under More → Background tasks; displayed task fields include `running`, `enabled`, `lastStatus`, `lastRunAt`, `lastDurationMs`, `lastError` and `nextRunAt`. Failed counts are latest task results, not a 24h request error rate. All entries remain inspectable; the first five prioritize errors/running/recent work. No manual-run route is called.
- GET `/logs?order=desc&limit=5&level=error,warn,fatal`: a small Overview preview using existing LogSnapshot validation/parser/masking. It refreshes at the configured historical interval; no second log SSE socket. Retention limits still apply.
- GET `/usenet/library?limit=20&offset=...&sort=activity&dir=desc&q=...&statuses=...`: `{ entries, total }`, twenty rows per page, debounced name search and single status selection. Status is queued/inspecting/available/degraded/failed/streaming. Files, owner/origin, failure reason, rechecks and optional probe counts are displayed from the list response. The file list renders up to 100 files per entry. Library timestamps `addedAt`/`lastUsedAt` are ISO strings; recheck timestamps are epoch milliseconds. The view uses periodic REST/manual refresh; library SSE notifications are not used in this version.
- GET `/media-info`: summary of stored files, outcome counts, timings and ffprobe availability. The outcome window follows the server's 24 hourly buckets ending with the current hour, rather than calendar-day totals. A 404 suspends automatic retries and subordinate feeds until explicit refresh/reopening; older servers remain usable.
- GET `/media-info/live`, SSE `/media-info/live/stream`: `{ enabled, jobs, limits, ffprobe }`, raw change-only snapshots; default tick 1s with 15s comment heartbeat. Only job stage/kind/file/byte count is shown; first 50 jobs are rendered. Named `finished` events exist upstream but are not consumed here: totals and history use the configured periodic refresh and manual Refresh. No probe is started/cancelled.
- GET `/media-info/probes?limit=20&offset=...&q=...&outcome=...`: `{ items, total, capped }`, recorded attempts with stored/applied/empty/failed/timeout/cancelled outcomes, errors, bytes/tracks and timings.
- GET `/media-info/files?limit=20&offset=...&q=...`: `{ items, total, capped }`, stored file metadata and container-ordered video/audio/subtitle tracks. Capped counts display a `+` suffix. File duration is seconds, track bitrate uses bits/s. “Applied” probes without a trusted identity were used once and need not appear as stored files.

New contracts use runtime shape checks before render/SSE acceptance. Library/probe/file responses are projected to displayed fields: passwords, source NZB URLs, archive layouts, release identities and unknown metadata are dropped before Resource/sample retention. Credential-shaped strings in displayed metadata/errors are masked using the existing log text masker. This retains existing pattern-based limitations; it is not a promise to remove all possible secrets from arbitrary prose.

Usenet now also renders the existing `pool.globalDownloadsInUse`, `globalDownloadMax`, `globalDownloadsOnWire`, `globalDownloadsWaiting` and segment-cache hit/miss/disk metrics. Permits in use may include work not transferring yet; waiting alone is not evidence of a stalled player. A cache with no hits/misses shows “No requests yet,” not a fabricated 0% hit rate. Missing/nonfinite numeric fields show unavailable.

System/warnings are Overview-only resources, with one retained snapshot each; Background tasks, Library and Media Info are mounted only on their screens. Existing foreground/offline suspension, session cookies, auth failure suspension, manual refresh and static-only PWA caching apply. Newly added Overview preferences append to older saved layouts without losing pin/order values. The removed task section is filtered out of saved layouts, preserving all other sections' pins/order.

## Retained usage and addon monitoring (2026-10-06)

- Usenet recorded activity uses existing `/usenet/stats` `totals` and `throughput` buckets for bytes/articles/errors; `firstSeenAt` is the earliest retained activity, not a completeness guarantee. Charts do not connect across missing buckets or manufacture samples. One historical bucket displays its value instead of waiting for live samples. Provider rates/averages use the selected stats window; historical rows distinguish removed providers from configured providers outside a received, usable live pool snapshot. A failed or missing live feed does not prove provider absence. No historical per-provider graph endpoint is invented.
- Overview and Streams show the configured global stream cap (`summary.connectionLimit=0` means unlimited) and separately count reported sessions with `activeReads>0`. Upstream admission uses open reads, not activity states; idle sessions use no slot. Replica snapshots can omit open reads, so the count is not authoritative global occupancy.
- `BandwidthOverview.seriesByUser` provides individual sparse bucket series and an optional `aggregated` line for users outside the server's individual-series limit. Empty username without `aggregated` means unidentified streams, kept distinct from the combined line. Global gauges use `periodTotal`; per-user gauges only use `byUser[].bytes` when the selected/returned window is `30d`, matching configured limits. 24h/7d rows display totals and explain how to select the accounting period, without a mismatched percentage. Over-limit percentages remain visible while meters clamp to their maximum; zero limit is unlimited. No extra accounting-period request is made for short windows.
- Historical stream details show request count, last activity, recorded end and session span (`endedAt ?? lastSeenAt` minus `startedAt`). Span includes pauses/idle time and is not playback duration. Missing ends are labeled; inconsistent timestamp order yields an unavailable span.
- GET `/analytics/addons?range=24h|7d|all`: `{ total, customEndpoints, addons }`, mounted under More → Addon health. Rows expose `presetId`, `requests`, `share`, `errors`, `errorRate`, `errorKinds` and nullable `avgLatencyMs`. Unlike Usenet rates, addon `share`/`errorRate` are percentages from 0–100. `total` counts non-overridden preset requests; `customEndpoints` counts requests to overridden URLs, not distinct endpoint URLs. Those requests are not assigned per-addon error/latency rows. The supported upstream repository uses recent raw events for 24h/7d; both its 30d and all paths return all retained daily rollups without a 30-day filter. AIOMobile therefore omits 30d and labels all as All rollups. Collection/retention settings limit coverage, and empty data is not interpreted as healthy. No configure-page per-user contribution metrics are inferred.
- Addons reuse existing foreground/offline/auth suspension and periodic/manual refresh, retain one projected snapshot, and render twenty filtered/sorted rows per page with expandable request-share/error details. A 404 suspends automatic requests until explicit refresh/reopen/range selection. No addon tests/requests, task runs or provider/indexer operations are started. Unknown addon metadata is discarded before retention and credential-shaped displayed fields use existing pattern masking.
- New runtime checks validate bandwidth window/period metadata, user totals/limits/series, richer history fields, Usenet aggregate/bucket numeric values and historical provider markers, addon percentages/error-kind counts/nullable latency, and nonnegative integer stream-cap counts and active-read counts before rendering. These are checks for supported contracts, not a universal schema.
